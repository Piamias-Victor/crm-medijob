# Public apply page replaces T4S / board form as CRM Application entry

Matthieu needs job-board « Postuler » to land on a CRM page (like Weekly availability), not T4S (`tzportal`) or the site Supabase candidature form. Recruiters already process Applications in the CRM inbox; the missing piece is a public submit that writes the CRM DB directly with offer context (`boardListingId`).

Decision: ship `/postuler/[boardListingId]` as a public Next.js route (middleware + access allow like `/dispo`). Resolve the JobOffer by `boardListingId`; expose only title, métier, city, contract when status is `PUBLIEE` (else unavailable; unknown id → 404). Create an Application with source `PUBLIC_APPLY`, applicant `postalCode` (nullable column; required on this page as 5 digits), FR phone, mandatory consent (`SITE` + timestamp), optional message, and CV stored via existing blob (PDF/DOC/DOCX · 5 Mo · magic bytes · sanitized name · never a public URL). Shared Zod schema client/server. Anti-spam: invisible honeypot (filled → fake success, no write) + IP rate limit 5/hour via a **Prisma rate-limit table** (no Redis in stack; works across serverless instances). Privacy policy URL + retention copy from env — `[À COMPLÉTER]` in non-prod, **fail closed in production** via `validateServerEnv`. UI shell/tokens/thank-you pattern copied from `/dispo` (extract shared shell only if needed; dispo render unchanged). `noindex`. V1 excludes RDV, confirmation email, captcha, applicant dedup, Medijob site button changes, and any change to board ingest code. Inbox/detail show postal code + source; accept/refuse unchanged.
